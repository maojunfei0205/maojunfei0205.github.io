jvm

发表于2025-04-14|更新于2025-04-15|jvm
|浏览量:

以下是JVM基础架构的详细讲解，涵盖内存模型、对象生命周期和核心组件：

一、JVM内存模型

JVM内存分为以下几个核心区域，每个区域职责明确：

1. 堆内存（Heap）

  • 作用：存放所有对象实例和数组，是GC管理的主战场。
  • 分区：
    • 新生代（Young Generation）：
      • Eden区：对象初次分配的位置，占新生代的80%。
      • Survivor区（S0/S1）：用于存放Minor GC后存活的对象，采用复制算法避免碎片。
    • 老年代（Old Generation）：存放长期存活的对象（默认经历15次Minor GC存活的对象）。
    • 元空间（Metaspace）：JDK8+替代永久代，存储类元数据（如类结构、方法信息），使用本地内存，避免OOM。
  • 配置参数：
    • -Xmx/-Xms：堆最大和初始大小。
    • -XX:NewRatio=2：老年代与新生代的比例（2:1）。
    • -XX:MaxMetaspaceSize：限制元空间大小。

2. 栈内存（Stack）

  • 虚拟机栈：
    • 每个线程私有，存放栈帧（方法调用时的局部变量、操作数栈、动态链接、方法出口）。
    • StackOverflowError：栈深度超过限制（如递归未终止）。
    • 配置参数：-Xss（如-Xss1m设置栈大小为1MB）。
  • 本地方法栈：为Native方法服务，结构与虚拟机栈类似。
  • 程序计数器（PC Register）：
    • 线程私有，记录当前线程执行的字节码指令地址（Native方法时为undefined）。

3. 直接内存（Direct Memory）

  • 特点：通过ByteBuffer.allocateDirect()分配，绕过堆内存直接使用OS内存。
  • 优势：减少Java堆与Native堆的数据拷贝，提升NIO性能。
  • 风险：不受JVM GC管理，需手动释放或依赖Cleaner机制，可能导致OOM。

4. 非堆内存（Non-Heap）

  • 方法区（逻辑概念）：包含元空间（JDK8+）和运行时常量池。
  • 代码缓存（Code Cache）：存储JIT编译后的本地代码。

二、对象生命周期

1. 对象创建过程

  1. 类加载检查：检查类是否已加载、解析和初始化。
  2. 内存分配：
    • 指针碰撞（堆内存规整时）或空闲列表（内存不连续时）。
    • TLAB（Thread Local Allocation Buffer）：为线程预分配Eden区的小块内存，减少并发竞争。
  3. 初始化：将内存空间置零值（默认初始化）。
  4. 对象头设置：填充Mark Word（哈希码、GC分代年龄等）和类型指针（指向类元数据）。

2. 对象访问定位

  • 句柄池：
    • 堆中维护句柄池，包含对象实例数据和类型数据指针。
    • 优点：对象移动时（如GC）只需更新句柄，引用不变。
  • 直接指针（HotSpot默认）：
    • 引用直接指向对象内存地址，访问速度更快。

3. 对象内存布局

区域 内容
对象头 Mark Word（存储锁状态、GC标志等）、类型指针（指向类元数据）
实例数据 对象的字段（包括父类继承的字段）
对齐填充 保证对象大小为8字节的整数倍（提高内存访问效率）

三、其他核心组件

1. 执行引擎

  • 解释器：逐行解释字节码，启动速度快。
  • JIT编译器（Just-In-Time）：将热点代码编译为本地机器码（如C1/C2编译器）。
  • 垃圾回收器：负责堆内存的自动回收（如Serial、Parallel、CMS、G1等）。

2. 本地方法接口（JNI）

  • 允许Java代码调用C/C++等Native方法（如System.currentTimeMillis()）。

四、常见面试问题示例

  1. 堆内存和栈内存的区别？
    • 堆是线程共享的对象存储区，栈是线程私有的方法调用存储区。
  2. 元空间为什么会取代永久代？
    • 永久代大小固定易OOM，元空间使用本地内存且可动态扩展。
  3. 如何排查OutOfMemoryError: Java heap space？
    • 使用jmap生成堆转储，MAT分析大对象或内存泄漏。
  4. TLAB的作用是什么？
    • 减少多线程分配内存时的锁竞争，提升对象分配效率。
