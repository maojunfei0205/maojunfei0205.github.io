发表于2025-04-22|更新于2025-04-22|java
|浏览量:

一、线程池的基本概念

先从基础开始说起，线程池的作用大家应该都知道——它是用来管理和复用线程的。我们平时直接创建线程并执行任务，可能会面临一些问题，比如线程创建和销毁的开销，或者线程数过多导致系统资源紧张。线程池就能解决这个问题，简单来说，线程池通过提前创建一组线程，任务来了直接分配，线程池能复用这些线程，避免了频繁的线程创建和销毁。

线程池背后的思想是“线程池化”，这意味着我们只用提供一个任务，它就会把任务分配给池中的一个空闲线程去执行，执行完后这个线程会回到池子里，准备执行下一个任务。

二、线程池的常见参数

OK，接下来我们来聊聊线程池常见的参数。线程池并不是万能的，配置得好能让你的应用流畅运行，配置得不当可能会让你的服务器资源占用不合理，甚至崩溃。所以，面试官一般都会问这些常见的参数，看看你有没有搞明白。

线程池的核心类是 java.util.concurrent.ThreadPoolExecutor，它有四个非常重要的参数：

1. 核心线程数 corePoolSize

corePoolSize 是线程池中最基本的线程数。这个线程数是线程池在处理任务时最小的线程数。也就是说，线程池会保证至少有这么多线程在空闲状态下等待任务。即使线程池的任务数为零，线程池也不会主动销毁这些线程。

举个例子，如果你设置 corePoolSize 为 4，当任务数为零时，线程池会保留 4 个线程一直处于待命状态。

2. 最大线程数 maximumPoolSize

maximumPoolSize 是线程池允许的最大线程数。如果任务数量非常多，线程池中的线程数会逐渐增长，直到达到了最大线程数。如果任务数过多，线程池就会阻塞任务，直到有空闲的线程。

如果 corePoolSize 和 maximumPoolSize 的值相等，线程池就不会增加线程数，所有的任务都会放入队列中，等待空闲线程来处理。

3. 空闲线程存活时间 keepAliveTime

当线程池中的线程数超过核心线程数时，这些多出来的线程会在空闲时被销毁。但销毁线程不是立刻发生的，而是会等待一个“空闲时间”，这个时间就是 keepAliveTime。如果线程空闲时间超过这个设置，线程池就会把这些空闲线程销毁。

4. 任务队列 workQueue

workQueue 是一个阻塞队列，用来存放等待执行的任务。线程池中的任务如果提交得太快，线程池中没有足够的线程来处理，这些任务就会被放入队列中等待，直到有空闲线程来执行它们。常见的队列类型包括：

  • LinkedBlockingQueue：无界队列，任务数不受限制。
  • ArrayBlockingQueue：有界队列，队列满了就会导致新任务的拒绝。
  • SynchronousQueue：没有内部容量，每提交一个任务就会等待一个线程来取走。

如果队列的容量被占满了，且线程池中的线程数也达到了最大值，线程池就会拒绝处理新提交的任务。这个时候会根据 RejectedExecutionHandler 的配置来决定如何处理这些任务。

三、线程池的底层实现

聊到这里，大家一定有个问题：线程池到底是如何管理这些线程和任务的呢？说白了，线程池的底层其实就是通过一个生产者消费者模型来管理任务的。线程池的核心就是通过 ThreadPoolExecutor 来调度线程和任务。

  • 任务提交：当我们提交任务时，线程池会先尝试分配给一个空闲线程。如果没有空闲线程，并且线程池没有达到最大线程数，线程池会创建新的线程来执行任务。否则，它会把任务放入阻塞队列等待执行。
  • 线程回收：当线程池中有超过核心线程数的空闲线程时，这些线程会根据 keepAliveTime 的设置被销毁。销毁的线程会先被“死循环”阻塞一段时间，确保不会频繁地销毁和重建线程，保证了效率。
  • 拒绝策略：当队列满了，而且线程池也达到了最大线程数，线程池会启动拒绝策略。ThreadPoolExecutor 提供了几种拒绝策略，例如 AbortPolicy（默认），CallerRunsPolicy，DiscardPolicy 和 DiscardOldestPolicy。

例如，AbortPolicy 会抛出 RejectedExecutionException，而 CallerRunsPolicy 会将任务交给调用线程来执行。

四、线程池的一些实际应用场景

  1. Web 应用中的并发请求处理：线程池在 Web 应用中广泛应用。比如，在一个电商网站中，用户下单、查询库存、支付等操作可以分配给不同的线程池处理。这样，系统的性能和响应速度就能得到保证。
  2. 任务调度：比如，定时任务的调度，使用线程池可以避免频繁创建和销毁线程，从而提升任务执行效率。
  3. 并发计算：比如大数据处理，多个任务并行计算时，线程池能有效地管理和调度计算任务，保证资源的合理利用。

通过上面的分析，我们对线程池的参数和底层实现有了更清晰的理解。线程池不仅能帮助我们管理线程，还能提高系统的性能和可扩展性。在面试中，如果面试官问你线程池的工作原理，你可以从线程池的核心参数、底层实现以及实际应用等多个方面进行详细阐述，展示你对这个问题的理解。
